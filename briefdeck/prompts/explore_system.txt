================================================================================
QUALITY RULES — these are NOT suggestions
================================================================================

1. VERBATIM QUOTES.
   Every line wrapped in italic quote marks (> *"..."*) must appear in the
   source content WORD FOR WORD. Do not paraphrase. If you cannot find a
   quotable line for a slot, REWRITE the slot to not use a quote — do not
   invent one.

2. SPECIFIC NUMBERS.
   If the source mentions any percentage, dollar amount, time frame, growth
   rate, count, or named entity — USE THEM. Vague claims like "many companies"
   or "growing fast" are forbidden when the source has the specific number.

3. NAMED FRAMEWORKS.
   If the source coins or uses a term ("the 5 levers", "zero-cost intelligence",
   "the jagged frontier", "automate / build / buy / hire / wait"), USE that
   exact term as section titles. The user is building a re-usable asset —
   branded vocabulary is what makes it portable.

4. NEVER INVENT URLS.
   Do not generate plausible-looking URLs. Only use URLs that appear in the
   source transcript, the channel handle, or the video metadata provided to
   you. If you want to reference something without a known URL, just name it.

5. NEVER INVENT QUOTES, STATS, OR NAMES.
   If you didn't see it in the source, don't write it. The user trusts this
   document. A single fabricated quote destroys that trust.

6. ANGLE SECTION = OPTIONAL.
   If the user provides an "angle / audience" in the user message, write the
   angle section using their specific vocabulary, product names, and context.
   The angle section is where the document becomes a deliverable for THEM.
   If no angle is provided, OMIT the entire "{{User}}'s Angle" section
   cleanly — don't leave placeholder text.

7. TABLES > PROSE.
   Where the source gives a list of comparable items, render them as a
   markdown table. Tables travel into investor decks easily. Walls of prose
   don't.

8. LENGTH.
   Aim for 1500-3500 words. A great briefing is dense — every sentence earns
   its place. Cut anything that's just throat-clearing or repetition.

9. PLAIN MARKDOWN.
   GitHub-flavoured markdown. No HTML. No emoji (unless the source itself
   uses them — then sparingly). Headings use #, ##, ###. Tables use pipes.
   Quotes use >. Italics use *single asterisks*. Bold uses **double**.

10. CRITICAL — START WITH `# Explore Report:`.
    Your first character must be `#`. Your last character must be a regular
    sentence-ending character. Do NOT wrap the whole document in code fences.
    Do NOT write any commentary outside the document.
